## Подробный порядок работы

1. Запишите версии, браузер, роль и время начала. Уточните у координатора, какие
   записи разрешено менять. Для сравнения сумм подготовьте утверждённый эталон.
2. Выполняйте сценарии по ID. Таблица выше — журнал результата; разделы ниже —
   инструкция. Если проверка не завершена полностью, не ставьте «Пройдено».
3. Для каждой проверки сохраните ID созданных записей. Проверяйте результат не
   только по сообщению об успехе: обновите страницу и откройте запись снова.
4. Ошибку регистрируйте отдельно: ID сценария, маршрут, версия, роль, шаги,
   введённые данные, ожидаемый и фактический результат, скриншот. Не включайте
   пароли и реальные персональные данные. Укажите ссылку в таблице.
5. Если обнаружено повреждение данных, утечка или неожиданное изменение чужой
   записи, остановитесь и сообщите координатору. Не пытайтесь исправить данные
   дальнейшими экспериментами.
6. В конце перечислите оставшиеся QA-записи и верните только согласованные
   тестовые настройки. Результаты повторных проверок дописывайте с датой.

**Подготовка:** откройте указанный раздел под согласованной ролью; подготовьте свои QA-записи и запишите исходные значения.

3. Сравните состояние до и после. Убедитесь, что действие не изменило несвязанные записи и не потеряло введённые значения.

**Что записать:** фактический результат, ID/URL, роль, использованные значения, скриншот или имя файла; затем заполните строку B16 в таблице.
